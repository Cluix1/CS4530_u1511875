# Assignment 4: Fun Facts

An Android app that fetches random English facts and saves them locally with Room.

Open this folder as a project in Android Studio. Run the `app` configuration on an
emulator or Android device with API 24 or newer. Internet access is needed to fetch
new facts; previously saved facts and searching work offline.

## How to use

- Tap **Fetch a new fact** to fetch and save a fact. New facts appear first.
- Type in **Search saved facts** to filter the locally saved text immediately,
  ignoring case. Clear the field to see all facts again.
- Successfully fetching a fact clears the current search so the new fact is visible.
- Close and reopen the app to see the facts saved in the database.
- If fetching fails, saved facts remain available and the button lets you retry.

## Architecture

This follows the flat file structure and Room singleton pattern in Assignment 3,
and the Ktor `ApiClient` object and JSON configuration in `Example Code/HTTPReqDemoV2`.

- `FunFact`: Room entity with an autogenerated `@PrimaryKey`.
- `FunFactResponse`: separate serializable API model containing the fact text.
- `FunFactDatabase` / `FunFactDao`: singleton Room database and observable saved facts.
- `ApiClient`: singleton Ktor Android HTTP client with JSON deserialization and a timeout.
- `FunFactRepository`: singleton that calls Ktor and inserts the result into Room.
- `FunFactApplication`: holds the database, client, and repository singletons.
- `FunFactViewModel`: observes the repository, filters local facts, and handles fetching state.
  It has no direct database or HTTP client access.
- `FunFactViewModel.Factory`: constructs the ViewModel with its repository.
- `MainActivity` / `FunFactScreen`: display observable ViewModel state and forward user actions.

The list comes from Room's `Flow`, so successful inserts update the UI automatically.
Search filters this local list; it does not call the API. Each fetch gets its own
local ID, so the API returning the same text again does not cause a primary key conflict.

The [API documentation](https://uselessfacts.jsph.pl/) lists
`https://uselessfacts.jsph.pl/api/v2/facts/random?language=en` as the current endpoint.
The assignment's older `/random.json` endpoint redirects to it. The lecture example
also uses the current endpoint.

## Verification commands

From this folder, with the Android SDK and Java configured:

```sh
./gradlew :app:assembleDebug :app:lintDebug
./gradlew :app:connectedDebugAndroidTest
./gradlew clean
```

On Windows PowerShell, use `.\gradlew.bat` in place of `./gradlew`.
The instrumented tests require a running emulator/device. They check fetching and
Room insertion through the repository, live local search without network requests,
failure/retry behavior, and persistence after closing/reopening a disk database.
Network responses in these tests use Ktor's mock engine for repeatable results.

Verified on the API 37 emulator: debug build, lint (no errors), and all four
instrumented tests passed. A real API fetch was also checked in the app, and its
saved fact remained visible after force-stopping and reopening the app.
Gradle `clean` completed successfully before submission.
